자연어로 복지 혜택과 법령을 찾고, 검색 결과와 AI 요약을 확인하는 서비스

프로젝트 소개

필요한 복지 혜택이나 법령을 메뉴에서 일일이 찾는 대신, 자연어로 질문하고 결과를 확인하는 대화형 검색 서비스입니다. 검색 결과와 요약을 대화 안에서 단계적으로 보여주는 경험을 설계했습니다.

검색 결과와 AI 요약을 나눠, 기다리는 동안에도 정보를 보여주었습니다.

해결할 문제

검색 결과를 찾은 뒤에도 AI 요약이 끝날 때까지 응답을 기다리게 하면, 사용자는 정보를 이미 찾았는지 알 수 없습니다. 검색은 성공했지만 요약 생성만 실패했을 때 전체 응답을 오류로 바꾸는 것도, 이미 찾은 정보를 버리게 되는 문제였습니다.

클라이언트에서는 네트워크로 받은 데이터 한 덩어리가 이벤트 하나와 정확히 일치하지 않습니다. JSON 중간에서 끊겨 도착하거나 여러 이벤트가 함께 올 수 있어, 수신한 데이터를 바로 파싱하는 방식으로는 처리할 수 없었습니다.

선택한 방법

서버는 검색 결과 이벤트를 먼저 전송하고, 뒤이어 요약을 SSE 스트리밍으로 전달하도록 했습니다. 클라이언트는 검색 중·요청 진행 중·화면 애니메이션 중 상태를 나누어, 검색 결과가 도착하면 로딩을 끝내고 요약은 이어서 갱신하도록 구성했습니다.

SSE 파서는 TextDecoder와 문자열 버퍼를 사용해 불완전한 줄을 다음 수신까지 보관합니다. 완성된 이벤트를 결과·요약·오류로 구분하고, 요약이 실패하더라도 결과 카드가 이미 있으면 유지한 채 안내만 추가합니다. 요청 취소와 타임아웃도 공통 훅에서 처리하도록 했습니다.

질문 입력→검색 결과 먼저 표시→요약을 이어서 갱신

구현 결과와 검증

복지·법령 검색에서 같은 스트리밍 훅을 사용하면서, 검색 결과와 요약 생성의 상태를 독립적으로 다룰 수 있도록 했습니다. 테스트에는 결과·요약 이벤트의 순서, 수신 경계에서 잘린 이벤트의 복원, 요약 실패 시 기존 결과 유지 등의 조건을 포함했습니다.

계속 길어지는 메시지의 높이를 DOM에 표시하기 전에 계산했습니다.

해결할 문제

채팅에는 짧은 질문뿐 아니라 긴 요약과 결과 카드가 함께 쌓입니다. 전체 대화를 DOM으로 유지하면 화면 요소가 계속 늘어나고, 가상 스크롤을 사용하더라도 메시지마다 다른 높이를 알아야 표시 위치를 정할 수 있습니다.

특히 스트리밍 중에는 글자가 계속 추가되면서 줄 수가 달라집니다. 메시지의 높이를 고정값으로 가정하면 실제 내용과 차이가 생기고, 텍스트만 계산하면 아래에 붙는 카드나 법령 목록의 공간을 반영할 수 없습니다.

선택한 방법

Canvas로 텍스트 폭을 측정하고, 컨테이너 너비와 폰트 조건에 따라 줄바꿈과 높이를 계산하도록 했습니다. 웹 문서 편집기에서 다뤘던 텍스트 레이아웃 경험을 적용해, 이분 탐색으로 한 줄에 들어갈 길이를 찾는 측정 모듈을 구성했습니다.

텍스트의 높이에는 말풍선 여백과 행간을 반영하고, 결과 카드와 법령 목록의 추가 높이는 각 기능에서 계산해 합칩니다. 이 추정값을 TanStack Virtual의 estimateSize에 전달해 화면 주변의 메시지만 렌더링하도록 했습니다.

메시지 ID와 본문·요약 길이, 추가 콘텐츠 높이를 기준으로 계산 결과를 캐시합니다. ResizeObserver로 컨테이너 너비가 바뀌면 높이 캐시를 비워 다시 계산하고, 대화가 길어지면 오래된 캐시도 정리하도록 했습니다.

텍스트 폭·줄 수 계산+카드·목록 높이→가상 리스트에 높이 전달

구현 결과와 검증

메시지 전체를 먼저 DOM에 표시하지 않고도 가상 리스트에 필요한 높이를 추정할 수 있도록 했습니다. 텍스트 레이아웃과 메시지 높이 계산을 UI 밖으로 나누고, 메시지 유형과 내용에 따른 높이 계산을 테스트에 포함했습니다.

짧은 후속 질문에는 문맥을 잇고, 새로운 질문에는 이전 주제를 섞지 않았습니다.

해결할 문제

“장애인 고용 의무”를 검색한 뒤 “비율은?”이라고 물으면, 현재 문장만으로는 어떤 비율을 찾는지 알기 어렵습니다. 그렇다고 짧은 질문마다 이전 대화를 붙이면 “전세사기 피해”처럼 짧지만 새로운 질문에 엉뚱한 주제가 섞일 수 있습니다.

선택한 방법

법령 검색에서는 “그 조항”, “그러면” 같은 앞 대화를 가리키는 표현과, “비율”, “벌칙”, “예외” 등 특정 측면을 묻는 짧은 질문을 구분했습니다. 후속 질문으로 판단한 경우에만 최근 사용자 질문 두 개를 검색어에 보강하고, 충분히 구체적인 새 질문은 원문을 그대로 사용합니다.

문맥은 모델이 생성한 답변이 아닌 사용자 질문에서 가져옵니다. 초기화 성격의 입력은 앞선 문맥을 붙이지 않고, 현재 질문이 히스토리에도 들어 있는 경우 중복되지 않도록 제외합니다. 이 판단 로직은 검색 UI와 분리한 함수로 관리했습니다.

구현 결과와 검증

질문을 반복해서 길게 입력하지 않고도 대화를 이어갈 수 있도록 하면서, 짧은 새 주제가 이전 질문과 섞이지 않도록 했습니다. “비율은?”과 “그 조항 벌칙은?”의 문맥 연결, 새 주제 유지, 초기화 입력, 히스토리 중복 등의 조건을 테스트했습니다.
