브라우저에서 LiDAR 점군을 확인하고, 3D 바운딩 박스를 편집하는 라벨링 도구

프로젝트 소개

PCD 파일을 브라우저에서 열어 차량과 보행자의 3D 바운딩 박스를 만들고 편집하는 웹 도구입니다. 카메라 이미지와 calibration 정보를 함께 불러오면 3D 박스를 이미지 위에 투영해 확인할 수 있습니다.

파일을 읽는 작업과 화면을 조작하는 작업을 분리했습니다.

해결할 문제

PCD는 수많은 점의 위치와 강도 정보를 담는 파일입니다. 파일을 열면 헤더를 읽고, 데이터 형식에 맞춰 각 점을 해석한 뒤 3D 장면에 전달해야 합니다. 이 계산을 화면 이벤트와 같은 메인 스레드에서 처리하면 파일을 읽는 작업이 사용자 입력 처리를 지연시킬 수 있습니다.

또한 파일 파싱을 다른 스레드로 옮기는 것만으로 끝나지는 않습니다. 원본 파일과 파싱한 점 배열을 주고받을 때 데이터를 매번 복사하면, 데이터 크기만큼 전송 비용과 메모리 사용이 늘어납니다.

선택한 방법

파일을 ArrayBuffer로 읽어 Web Worker에 전달하고, Worker가 점의 위치와 강도를 Float32Array로 생성하도록 했습니다. 입력 버퍼와 결과 배열의 버퍼를 transfer 목록에 넣어, 버퍼를 복제하는 대신 소유권을 넘기도록 했습니다.

Worker는 요청마다 생성하고 성공·실패·취소 시 종료합니다. 파싱 오류는 응답으로 전달해 로딩 상태와 분리하고, 사용자가 다른 파일을 열 수 있도록 했습니다.

PCD 파일 읽기→Worker에서 파싱→버퍼 소유권 전달→3D 장면에 표시

파싱 이후의 렌더링도 조절

파싱은 CPU 작업이고, 점군을 계속 그리는 것은 별도의 렌더링 작업입니다. 기본 화면은 변경이 있을 때 그리는 demand 모드로 두고, 고해상도 화면에서 렌더링 해상도가 과도하게 커지지 않도록 DPR 상한을 1.5로 설정했습니다.

표시할 점도 25%·50%·100%로 조절할 수 있게 했습니다. 원본 데이터는 유지하면서 렌더링에 사용할 점만 일정 간격으로 추출해, 좌표계를 바꾸지 않고 표시 부하를 낮출 수 있도록 했습니다. FPS 통계를 켠 경우에만 연속 렌더링 모드로 전환합니다.

구현 결과와 검증

파일 디코딩과 화면 조작의 실행 경로를 분리하고, 기기 상황에 맞춰 표시할 데이터 양을 조절할 수 있는 구조를 만들었습니다. binary·ascii 파싱 결과의 일치, 잘못된 데이터 길이, 미지원 포맷 등의 테스트로 파일 해석 규칙을 확인하도록 했습니다.

3D 박스를 사진 위에 표시하려면, 서로 다른 좌표계를 연결해야 했습니다.

해결할 문제

점군만 봐서는 박스가 실제 차량이나 보행자의 어느 부분을 감싸는지 판단하기 어려울 수 있습니다. 이를 카메라 사진과 함께 확인하려면 LiDAR 공간의 3D 위치를 사진 위의 픽셀 위치로 바꿔야 합니다.

3D 좌표를 이미지 크기에 맞춰 단순히 축소하는 것으로는 맞지 않습니다. 센서와 카메라 사이의 위치·회전, 카메라의 초점거리와 렌즈 왜곡을 함께 반영해야 합니다. 카메라 뒤에 있는 점이나 깊이가 0에 가까운 점을 그대로 계산하면 뒤집힌 좌표나 유효하지 않은 값도 생길 수 있습니다.

선택한 방법

외부 파라미터로 LiDAR 좌표를 카메라 좌표로 변환하고, 깊이로 나눠 정규화한 뒤 렌즈 왜곡을 적용했습니다. 마지막으로 내부 파라미터를 사용해 픽셀 위치를 구했습니다. 일반 렌즈와 어안 렌즈는 왜곡 모델을 구분했습니다.

같은 카메라로 여러 점을 처리할 때는 행렬과 파라미터를 미리 준비하는 투영 함수를 만들어 재사용했습니다. 카메라 뒤에 있는 점과 계산 결과가 유한하지 않은 점은 실패 사유를 구분해 반환하고, 입력 행렬과 왜곡 계수도 검증하도록 했습니다.

LiDAR 좌표→카메라 좌표→렌즈 왜곡 적용→이미지 픽셀

눈으로 맞아 보이는 것 이상으로 확인

카메라 이미지에 3D 박스를 겹쳐 보여주고, 편집 결과를 두 화면에서 확인할 수 있도록 했습니다. 투영 계산은 화면 컴포넌트 밖으로 분리했으며, OpenCV로 생성해 저장한 기준값과 결과를 대조하는 골든 테스트를 작성했습니다. 일반 렌즈와 어안 렌즈 모델 모두 기준 좌표와 소수점 셋째 자리 수준으로 비교합니다.

한 번의 드래그를, 한 번의 실행 취소로 되돌리도록 했습니다.

해결할 문제

박스를 이동하거나 회전하면 드래그 중에도 계속 값이 바뀝니다. 이 중간 상태를 전부 편집 이력에 저장하면, 사용자는 한 번 움직인 박스를 되돌리기 위해 실행 취소를 여러 번 눌러야 합니다.

반대로 최종 값만 저장하면서 다른 화면은 그 값만 읽게 하면, 드래그 도중 카메라 사진에 표시된 박스가 현재 3D 박스를 따라오지 못합니다. 실시간으로 보이는 상태와 이력에 남길 상태를 나눌 필요가 있었습니다.

선택한 방법

드래그 중에는 Three.js 객체를 조작하고, 위치·회전·크기를 별도의 미리보기 상태에 전달해 카메라 오버레이가 따라오도록 했습니다. 마우스를 놓을 때 실제 변경이 있었으면 최종 값을 편집 스토어에 한 번 반영하고 미리보기 상태를 지웠습니다.

회전은 quaternion으로 저장하고, 크기 조작으로 생긴 객체의 scale은 박스 크기에 반영한 뒤 1로 초기화했습니다. 드래그 도중 선택 변경이나 삭제 등으로 컴포넌트가 사라질 때도 미리보기 상태가 남지 않도록 정리했습니다.

드래그 시작→3D·2D 미리보기 갱신→종료 시 한 번 저장

선택과 도구 변경은 편집 이력에서 제외

Zustand와 zundo로 박스 데이터와 순서만 이력에 남겼습니다. 선택한 박스, 이동·회전 모드, 스냅 설정, 표시할 점의 비율 같은 UI 상태는 이력에서 제외하고, 박스 데이터가 바뀌지 않으면 기록을 추가하지 않도록 했습니다.

구현 결과와 검증

드래그 중의 실시간 표시와 실행 취소의 작업 단위를 분리했습니다. 스토어 테스트에는 박스 추가의 undo/redo, 선택 변경 시 이력이 늘어나지 않는 조건, 잠긴 박스의 수정·삭제 제한 등을 포함했습니다. 파일 열기 → 박스 생성 → 실행 취소의 사용자 흐름을 확인하는 E2E도 작성했습니다.
