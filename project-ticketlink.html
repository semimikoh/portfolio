유형별로 폼을 따로 만들면 어떤 일이 생길까?

실제 응모·당첨 관리자 화면에는 20개 이상의 필드와 3개 응모 유형이 있었습니다. 유형별로 폼을 따로 만들면 공연 정보처럼 같은 항목도 여러 곳에서 수정해야 했습니다.

React Hook Form 기반으로 폼을 7개 섹션으로 나누고, 공통 섹션과 유형별 섹션을 조합했습니다. 등록·수정 화면에서도 같은 섹션을 재사용하고, 옵션에 따라 달라지는 필수 조건은 Zod 스키마로 검증했습니다.

항목을 복사하는 대신 섹션을 조합해, 요구사항 변경을 해당 섹션과 검증 규칙 안에서 다룰 수 있도록 했습니다.

위 응모 유형과 입력 항목은 이 구조를 보여주기 위해 단순화한 예시입니다.

기존 서비스와 함께 확장

JSP Admin은 유지하면서 신규 화면에 React를 도입했습니다. JSP·AngularJS·React가 공존하는 글로벌 환경에서는 한국어·영어·일본어·중국어를 공통 i18n 모듈로 처리하고, 동적 DOM과 번역 리소스 로딩 시점의 차이도 다뤘습니다.
